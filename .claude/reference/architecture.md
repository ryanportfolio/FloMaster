# Architecture

> System flow, auth strategy, state management, cross-cutting structure. Keep it terse: pointers into code, not essays.

- Static Astro site, no backend. Pages in `src/pages/`, shared layout `src/layouts/Base.astro` (review bar, header with license line, footer, mobile sticky bar).
- Every business fact lives in `src/data/facts.ts` with a code (P01...), value, owner question and status. Pages render facts through `src/components/Fact.astro` (use `plain` inside links and buttons). Photos go through `src/components/Photo.astro`, which adds the "replace with a real photo" tag. `/review` lists every open fact.
- Tag state: `<html class="tags-on">`, set before paint by an inline head script from `?tags=` or `localStorage["fm-tags"]`; default off. `TagSwitch.astro` toggles it. `PUBLIC_BUILD=1` drops tags, the review bar, `noindex` and the tag markup.
- Other data: `src/data/services.ts` (service pages, sample price ranges), `reviews.ts` (sample reviews), `area.ts` (cities and ZIPs, unchecked).
- Booking is front-end only: `src/pages/book/index.astro` validates four fields and stores the booking in `sessionStorage["fm-booking"]`; `/book/confirmed` reads it. The phone number is shared with callback forms through `sessionStorage["fm-phone"]`. Nothing is sent anywhere.
- Brand tokens and the wave pattern are in `src/styles/global.css`; the logo is generated by `scripts/build-logo.mjs`.
